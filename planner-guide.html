Planner 사용 가이드

글로 화면을 설명하면, 프로토타입이 나옵니다

Planner는 여러분이 만들고 싶은 화면을 글(프롬프트)로 설명하면, 김반장 디자인 시스템의 검증된 컴포넌트로 조립한 프로토타입 HTML을 만들어 줍니다. 디자인·코딩 지식 없이 화면의 목적과 데이터만 설명하면 됩니다. 이 가이드는 좋은 프롬프트를 쓰는 법을 짧게 정리한 것입니다.

빠른 이동

작동 방식 프롬프트 4원칙 복붙 템플릿 예시 시스템이 알아서 하는 것 화면 확인법 잘 안 될 때 하지 말 것

작동 방식

요청 → 3단계로 받기

1

만들 화면을 정하고, 아래 템플릿으로 프롬프트를 씁니다

"무엇을 하는 화면인지 · 어떤 데이터가 있는지 · 어떤 동작을 하는지"를 평범한 말로 설명합니다.

2

Planner에게 보내고, "다음"으로 이어 받습니다

한 화면을 ① 마크업(뼈대) → ② 동작 목록 → ③ 최종 HTML 3단계로 나눠 만듭니다. 각 단계 끝에서 다음이라고 입력하면 다음 단계로 넘어갑니다. 한 번에 다 만들면 응답이 길어 끊기기 때문에 나눠 받습니다.

3

받은 HTML을 브라우저에서 열어 확인합니다

왼쪽 메뉴로 상태별 화면을 보거나(시나리오), 직접 입력·클릭하며 흐름을 확인합니다(인터랙티브).

프롬프트 4원칙

이 네 가지만 지키면 됩니다

원칙 1

제품 의도를 쓰세요

무엇을 하는 화면인지, 어떤 데이터(컬럼·필드)가 있는지, 어떤 동작(검색·등록·삭제…)을 하는지. 색·여백·폰트는 쓰지 마세요 — 시스템이 알아서 맞춥니다.

원칙 2

화면 성격을 밝히세요

조회·목록 / 등록·수정 / 확인 중 무엇인지 적으세요. 성격에 맞는 레이아웃·규칙이 자동으로 적용됩니다.

원칙 3

시나리오는 맡기세요

"데이터 있음만"처럼 개수를 제한하지 마세요. 빈 화면·로딩·오류 같은 상태는 시스템이 알아서 포함합니다.

원칙 4

큰 화면은 나누세요

위·아래로 나뉜 복잡한 화면은 한 번에 요청하지 말고 영역별로. 예시 데이터는 3~5행이면 충분합니다.

복붙 템플릿

이 틀에 채워서 보내세요

대괄호 부분만 화면에 맞게 바꾸면 됩니다. 시나리오·컴포넌트·스타일은 일부러 비워 둡니다 — 마지막 줄이 시스템에게 맡기라고 알려 줍니다.

prompt template 
"[페이지 이름]" 페이지를 만들어줘.
- 성격: 조회·목록 / 등록·수정 / 확인 중 하나
- 목적: 사용자가 무엇을 하는 화면인지 한두 문장
- 데이터/필드: 주요 컬럼·필드 + 종류(숫자·날짜·통화·빈값)
- 주요 동작: 검색·필터·정렬·등록·수정·삭제·전송 등
- (특이한 점만 평범한 말로: 예) "컬럼이 많아 가로로 스크롤된다")

시나리오·빈/로딩/오류 상태·컴포넌트·스타일은 디자인 시스템 규칙을 따른다.
팁 · 화면이 크면 "예시 데이터 3~5행", 화면이 여러 개면 "영역별로 따로" 만들어 달라고 덧붙이세요.

예시

그대로 써도 되는 프롬프트

조회·목록 자재 입고 내역 
"자재 입고 내역" 조회 페이지를 만들어줘.
- 성격: 조회·목록.
- 목적: 현장의 자재 입고 내역을 검색·조회한다.
- 검색/필터: 자재명·입고번호 검색, 입고상태 필터, 입고기간(날짜 범위).
- 데이터: 입고번호·자재명·규격(텍스트), 수량(숫자), 단가·금액(통화),
  입고일(날짜), 입고상태. 행 선택.
- 동작: 행별 상세·삭제, 우측 상단 "자재 입고 등록", 엑셀 다운로드.
- 예시 데이터 4~5행.
컴포넌트·스타일·시나리오는 디자인 시스템 규칙을 따른다.

이렇게 나옵니다 · 상단 검색·필터 바 + 데이터 테이블 + 총 건수, 데이터있음·검색결과없음·로딩·오류 화면을 각각 메뉴로 전환. 삭제는 확인창으로.

등록·입력 자재 등록 폼 
"자재 등록" 폼 페이지를 만들어줘.
- 성격: 등록·입력 폼.
- 입력 필드: 자재명(텍스트), 담당자(검색해서 한 명 선택),
  적용 공종(여러 개 선택 — 태그로 표시), 단가(통화), 수량(숫자),
  첨부 이미지(드래그&드롭 업로드, 썸네일 클릭 시 크게 보기).
- 하단에 취소 / 등록 버튼.
컴포넌트·스타일·시나리오는 디자인 시스템 규칙을 따른다.

이렇게 나옵니다 · 검색형 선택·다중 선택·파일 업로드·이미지 확대까지 시스템 컴포넌트로 동작. 신규·수정·검증 오류 상태 포함.

맡겨도 되는 것

시스템이 알아서 하는 일

아래는 여러분이 적지 않아도 시스템이 규칙대로 처리합니다. 오히려 직접 지정하면 일관성이 깨집니다.

  • 컴포넌트 선택 — 검색은 검색 바로, 확인창은 Alert로, 입력 폼은 Modal로 등 상황에 맞게.
  • 모든 스타일 — 색·여백·타이포·테두리. 디자인 시스템 토큰으로 통일됩니다.
  • 상태 화면 — 빈 화면·로딩·오류, 그리고 그것을 어디에 표시할지.
  • 인터랙션 — 검색·정렬·행 선택·다중 선택·파일 업로드·이미지 확대 같은 동작.
  • 표 기본 요소 — 엑셀 다운로드·테이블 설정 버튼, 총 건수, 숫자 우측 정렬 등.

결과 확인

만든 화면 보는 두 가지 방법

시나리오 보기

왼쪽 메뉴로 각 상태(데이터있음·빈 화면·로딩·오류 등)를 바로 띄워 검토합니다. 직접 조작하지 않아도 모든 상황을 한눈에 볼 수 있어요.

인터랙티브 보기

실제로 입력·클릭하며 흐름을 확인합니다. 검색·선택·다음 단계 이동 등이 진짜로 동작하는지 보세요.

문제 해결

잘 안 될 때

"응답을 완료하지 못했습니다" / "연결할 수 없습니다"

화면이 너무 큽니다. 시나리오 2~3개, 예시 데이터 3~5행으로 줄이고, 위·아래로 나뉜 화면은 영역별로 따로 요청하세요. 그리고 단계(Phase)를 다음으로 나눠 받으세요.

"시스템에 없는 컴포넌트입니다"

디자인 시스템에 없는 요소가 필요한 경우입니다. 디자이너에게 컴포넌트 추가를 요청한 뒤 진행하세요. Planner가 임의로 만들지 않는 것이 정상입니다.

규칙대로 안 나오는 것 같다

Planner 프로젝트 지식을 최신으로 동기화했는지 확인하세요. 디자인 시스템이 업데이트되면 동기화해야 새 규칙이 반영됩니다.

체크리스트

해도 되는 것 · 하지 말 것

✓ 이렇게

  • 목적·데이터·동작을 평범한 말로 설명
  • 화면 성격(조회/등록/확인)을 밝히기
  • 큰 화면은 영역별로 나눠 요청
  • 시나리오·스타일은 시스템에 맡기기

✕ 이건 피하기

  • "시나리오 1개만"처럼 개수 제한
  • 색·여백·폰트 크기 픽셀 지정
  • 한 메시지에 여러 화면 한꺼번에
  • 없는 컴포넌트를 만들라고 요청

막히거나 새 컴포넌트가 필요하면 디자이너에게 문의하세요. 이 가이드는 김반장 3.0 디자인 시스템을 기준으로 합니다.
