빠른 이동

작동 방식 프롬프트 4원칙 예시 시스템이 알아서 하는 것 화면 확인법 잘 안 될 때 하지 말 것

작동 방식

0

입력 · 복붙 템플릿으로 프롬프트를 씁니다

아래 템플릿의 대괄호 부분만 만들 화면에 맞게 바꿔, 프로젝트 대화창에 붙여넣어 보냅니다. 적을 건 화면의 목적과 데이터뿐이에요. 데이터가 없을 때·불러오는 중·오류가 났을 때 같은 화면이나, 어떤 버튼·색을 쓸지는 직접 정하지 않아도 시스템이 규칙대로 알아서 만들어 줍니다.

prompt template 
"[화면 이름]" 화면을 만들어줘.
- 형태: 페이지 / 모달 중 하나
- 성격: 조회·목록 / 등록·수정 / 확인 중 하나
- 목적: 사용자가 무엇을 하는 화면인지 한두 문장
- 데이터/필드: 주요 컬럼·필드 + 종류(숫자·날짜·통화·빈값)
- 주요 동작: 검색·필터·정렬·등록·수정·삭제·전송 등
- 플로우: 여러 화면이면 이어지는 순서 — 예) 목록 → 등록 모달 → 완료
- (특이한 점만 평범한 말로: 예) "컬럼이 많아 가로로 스크롤된다")
팁 · 화면이 크면 "예시 데이터 3~5행", 화면이 여러 개면 "영역별로 따로" 만들어 달라고 덧붙이세요.
1

로우파이 프로토타입 · 디자인 시스템이 만듭니다

로우파이 프로토타입은 화면의 뼈대와 상황별 화면(시나리오)을 확인용으로 조립한 결과물입니다 — 실제 클릭·입력 동작은 아직 없고, 무엇이 어디에 놓이는지와 어떤 상황이 있는지를 확정하는 단계예요. 데이터있음·빈 화면·로딩·오류 같은 기본 상황은 물론, 값·상태·권한에 따라 갈라지는 화면도 함께 챙겨 만들어 줍니다. 결과는 HTML 코드로 오니, 저장해서 열어 하나씩 확인하고 빠진 상황이 보이면 그 부분만 더 요청하면 됩니다.

크롬 환경에서 인터넷 연결이 필요합니다!

프로토타입은 디자인 시스템의 스타일·컴포넌트를 온라인에서 불러옵니다. Claude 대화창 미리보기로는 스타일이 적용되지 않으니, 받은 코드를 .html로 저장한 뒤 Chrome으로 열어 확인하세요.

2

Figma 추출 · 확정된 화면을 보관·공유합니다

구조·시나리오가 확정되면 화면을 Figma 아카이브로 옮깁니다. HTML 파일을 하나씩 열지 않아도 팀이 전체 흐름을 한눈에 보고 코멘트를 달 수 있고, 디자이너에게 기획을 넘기는 지점이기도 합니다.

어떻게 올리나요 — 프로토타입을 만든 같은 대화창에 "피그마에 올려줘"라고 하면, 확정된 화면이 아래 아카이브 파일에 자동으로 정리·업로드되고 열어볼 링크를 돌려받습니다. 이미 올린 걸 고쳤다면 "피그마도 업데이트해줘".

업로드 위치 · KBZ 3.0 프로토타입 아카이브 (Figma 파일)

이렇게 정리됩니다 — 시나리오마다 프레임 하나 · 화면 흐름 순서대로 배치 · 게시된 라이브러리 컴포넌트로 재조립 · 날짜·작성자별로 기록(같은 대화에서 만든 건 한 페이지에 모임).

거꾸로도 반영돼요 · Figma에서 문구·순서·컴포넌트를 조금 고친 뒤 "HTML도 그렇게 고쳐줘"라고 하면, 그 변경을 읽어 원본 HTML에 반영합니다. 단 원본은 언제나 HTML이라, 반영 뒤엔 HTML을 기준으로 관리하세요.
이럴 땐 멈춰요 · 사소한 수정마다 매번 올리지 말고 검토가 한 차례 끝난 시점에 남기세요. 라이브러리가 아직 게시(Publish)되지 않았거나 시스템에 없는 컴포넌트가 필요하면 추출이 멈추니, 그때는 디자이너에게 문의하세요.

프롬프트 4원칙

이 네 가지만 지키면 됩니다

원칙 1

제품 의도를 쓰세요

무엇을 하는 화면인지, 어떤 데이터(컬럼·필드)가 있는지, 어떤 동작(검색·등록·삭제…)을 하는지. 색·여백·폰트는 쓰지 마세요 — 시스템이 알아서 맞춥니다.

원칙 2

화면 성격을 밝히세요

조회·목록 / 등록·수정 / 확인 중 무엇인지 적으세요. 성격에 맞는 레이아웃·규칙이 자동으로 적용됩니다.

원칙 3

시나리오는 맡기세요 — 로우파이의 핵심

"데이터 있음만"처럼 개수를 제한하지 마세요. 빈 화면·로딩·오류는 물론 조건에 따라 갈리는 화면까지 시스템이 기본적으로 챙겨 줍니다. 빠진 게 있으면 검토하며 더 요청하면 돼요.

원칙 4

큰 화면은 나누세요

위·아래로 나뉜 복잡한 화면은 한 번에 요청하지 말고 영역별로. 예시 데이터는 3~5행이면 충분합니다.

예시

그대로 써도 되는 프롬프트

조회·목록 자재 입고 내역 
"자재 입고 내역" 조회 페이지를 만들어줘.
- 성격: 조회·목록.
- 목적: 현장의 자재 입고 내역을 검색·조회한다.
- 검색/필터: 자재명·입고번호 검색, 입고상태 필터, 입고기간(날짜 범위).
- 데이터: 입고번호·자재명·규격(텍스트), 수량(숫자), 단가·금액(통화),
  입고일(날짜), 입고상태. 행 선택.
- 동작: 행별 상세·삭제, 우측 상단 "자재 입고 등록", 엑셀 다운로드.
- 예시 데이터 4~5행.
컴포넌트·스타일·시나리오는 디자인 시스템 규칙을 따른다.

이렇게 나옵니다 · 상단 검색·필터 바 + 데이터 테이블 + 총 건수, 데이터있음·검색결과없음·로딩·오류 화면을 각각 메뉴로 전환. 삭제는 확인창으로.

등록·입력 자재 등록 폼 
"자재 등록" 폼 페이지를 만들어줘.
- 성격: 등록·입력 폼.
- 입력 필드: 자재명(텍스트), 담당자(검색해서 한 명 선택),
  적용 공종(여러 개 선택 — 태그로 표시), 단가(통화), 수량(숫자),
  첨부 이미지(드래그&드롭 업로드, 썸네일 클릭 시 크게 보기).
- 하단에 취소 / 등록 버튼.
컴포넌트·스타일·시나리오는 디자인 시스템 규칙을 따른다.

이렇게 나옵니다 · 검색형 선택·다중 선택·파일 업로드·이미지 확대까지 시스템 컴포넌트로 동작. 신규·수정·검증 오류 상태 포함.

맡겨도 되는 것

시스템이 알아서 하는 일

아래는 여러분이 적지 않아도 시스템이 규칙대로 처리합니다. 오히려 직접 지정하면 일관성이 깨집니다.

  • 컴포넌트 선택 — 검색은 검색 바로, 확인창은 Alert로, 입력 폼은 Modal로 등 상황에 맞게.
  • 모든 스타일 — 색·여백·타이포·테두리. 디자인 시스템 토큰으로 통일됩니다.
  • 상태 화면 — 빈 화면·로딩·오류, 그리고 그것을 어디에 표시할지.
  • 인터랙션 — 검색·정렬·행 선택·다중 선택·파일 업로드·이미지 확대 같은 동작.
  • 표 기본 요소 — 엑셀 다운로드·테이블 설정 버튼, 총 건수, 숫자 우측 정렬 등.

결과 확인

로우파이 화면 검토하기

시나리오 보기

받은 HTML을 브라우저에서 열고, 왼쪽 메뉴로 각 상태·조건별 화면을 하나씩 띄워 봅니다. 데이터있음·빈 화면·로딩·오류는 물론 조건에 따라 갈리는 화면까지, 직접 조작하지 않아도 한눈에 볼 수 있어요.

이때 확인할 것

필요한 시나리오가 다 있는지, 데이터·필드 구성과 화면 흐름이 의도대로인지 봅니다. 빠지거나 어긋난 부분이 있으면 그 부분만 다시 요청하세요.

참고 · 로우파이는 구조와 시나리오를 확정하는 단계라 클릭·입력이 실제로 동작하진 않습니다(검색·정렬 컨트롤은 보이되 걸러지지 않음). 실제 동작하는 UI는 하이파이 단계에서 디자이너가 이어받습니다.

문제 해결

잘 안 될 때

"응답을 완료하지 못했습니다" / "연결할 수 없습니다"

화면이 너무 큽니다. 시나리오를 줄이지 말고(로우파이의 핵심이므로), 화면을 영역별로 나눠 각각 요청하세요. 예시 데이터는 3~5행이면 충분합니다.

"시스템에 없는 컴포넌트입니다"

디자인 시스템에 없는 요소가 필요한 경우입니다. 디자이너에게 컴포넌트 추가를 요청한 뒤 진행하세요. 시스템이 임의로 만들지 않는 것이 정상입니다.

규칙대로 안 나오는 것 같다

프로젝트 지식을 최신으로 동기화했는지 확인하세요. 디자인 시스템이 업데이트되면 동기화해야 새 규칙이 반영됩니다.

✓ 이렇게

  • 목적·데이터·동작을 평범한 말로 설명

  • 색·여백·폰트 크기 픽셀 지정
  • 한 메시지에 여러 화면 한꺼번에
  • 없는 컴포넌트를 만들라고 요청

막히거나 새 컴포넌트가 필요하면 디자이너에게 문의하세요. 이 가이드는 김반장 3.0 디자인 시스템을 기준으로 합니다.
