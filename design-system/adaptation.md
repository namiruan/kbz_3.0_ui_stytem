# 반응형 & 다크모드

> **언제 참조하나:** 레이아웃 결정·테마 처리 시 모든 사람

## 반응형 & Breakpoint

김반장 3.0은 **데스크톱을 기준으로 설계하고 모바일까지 지원한다.**
앱 웹뷰 전환에 따라 `sm`(<768px)이 정식 지원 범위에 포함된다.

| Breakpoint | 너비 | 대응 디바이스 | 지원 |
|------------|------|--------------|------|
| sm | < 768px | 모바일 (앱 웹뷰) | 지원 |
| md | 768–1024px | 태블릿 | 지원 |
| lg | 1024–1440px | 데스크톱 | 기준 |
| xl | ≥ 1440px | 와이드 모니터 | 지원 |

레이아웃은 사이드바 + 콘텐츠가 화면 전체를 채운다. 콘텐츠 영역에 max-width를 두지 않는다.

### 규칙

- 컴포넌트는 컨테이너 너비에 따라 자연스럽게 stretch한다.
- Sidebar는 `lg` 이상에서만 고정. `md`에서는 collapse, `sm`에서는 기본 숨김.
- Modal은 `md` 이상에서 크기별 max-width 고정 + 화면 가운데 정렬. `sm`에서는 좌우 여백만 남기고 화면 폭을 채운다.
- `sm`에서 단독으로 놓이는 주요 액션은 `--height-loose`(48px)를 쓴다. 밀집 배치되는 보조 액션도 `--height-compact`(32px) 미만으로 내리지 않는다.
- **Density 정책은 breakpoint와 무관하게 동일하다**(→ `product.md`). 화면이 좁다고 밀도를 풀지 않는다.

> ⚠️ `sm` 대응은 컴포넌트별로 명시한다. 각 컴포넌트 문서의 `## 사용 지침`에 `sm` 동작이 없으면 아직 검증되지 않은 것이다.

### 여러 건을 나열하는 화면 — 표와 목록은 다르게 접힌다

같은 "여러 건 나열"이라도 사용자의 행동이 다르면 좁은 화면에서의 동작이 갈린다.

| | 데이터 테이블 (`table--data`) | 콘텐츠 목록 (게시판·자료실) |
|---|---|---|
| 사용자 행동 | 행끼리 **비교**하고 처리한다 | 한 건을 **골라 읽는다** |
| `sm`·`md` 동작 | **가로 스크롤. 컬럼 reflow 금지** | **세로 스택으로 reflow** |
| 근거 | 컬럼이 깨지면 비교 기능 자체가 사라진다 | 비교 대상이 아니라 항목 단위라 접어도 의미가 유지된다 |

> 💡 **판단 기준:** "사용자가 행끼리 비교하나?"
> YES → 데이터 테이블 (가로 스크롤) / NO, 하나 골라 읽는다 → 콘텐츠 목록 (세로 스택)

게시판·자료실처럼 읽을거리를 나열하는 화면을 데이터 테이블로 만들면 `sm`에서 가로 스크롤을
피할 방법이 없고, 업무 조회 화면과도 구분되지 않는다. 콘텐츠 계열 컴포넌트를 사용한다
(→ `components/_requests.md` REQ-001).

## 다크모드 정책

**현재 라이트 모드만 지원.** 토큰 구조는 다크모드 전환을 전제로 설계되어 있으나 정식 지원은 추후 결정.

### 규칙

- 컴포넌트에서 hex값 직접 사용 금지(다크모드 전환 시 일괄 갈아끼울 수 없게 됨).
- Surface, text, border, shadow는 반드시 Semantic 토큰 경유.
- 향후 다크모드 도입 시 Primitive 추가 + Semantic 매핑 변경만으로 전환 가능하도록 유지.

> ✅ DO — Semantic 경유. 다크모드 전환 시 토큰만 바뀌면 됨
> `.card { background: var(--color-surface-base); color: var(--color-text-body); }`

> ❌ DON'T — hex·Primitive 직접 참조 (다크모드 전환 불가)
> `.card { background: #ffffff; color: var(--color-gray-900); }`

> 💡 Semantic 토큰을 지키는 한 다크모드는 토큰 레벨 작업으로 끝난다. 컴포넌트 코드는 그대로.
